# Trait-Based Generic Emulator Architecture

## Overview

This document describes the design for transforming rmachine from a RISC-V-specific emulator into a generic emulation framework that can support multiple instruction set architectures (ISAs) through a trait-based architecture.

### Motivation

**Current Problems:**

The existing implementation has significant code duplication:
- Adding a single instruction requires changes in **9 different locations**
- Parser: manual operand parsing for each instruction
- Assembler: manual encoding logic for each instruction
- Executor: manual execution logic for each instruction
- Encoder/Decoder: manual bit manipulation

For 9 instructions, this results in ~500 lines of repetitive code across multiple modules.

**Vision:**

A generic emulator framework where:
- Adding a new instruction = one TOML entry + one Rust method
- Adding a new ISA = one TOML file + one Rust impl block
- Zero code duplication in the core emulator
- Type-safe, performant, and architecturally flexible

---

## Core Design Principle

**Key Insight:** Different CPU architectures are fundamentally different, but the **pattern** of emulation is the same:

1. Fetch instruction bytes
2. Decode to find instruction spec and operands
3. Execute using architecture-specific context
4. Update machine state

We can make the **pattern** generic while keeping architecture-specific details flexible through Rust's trait system.

---

## The InstructionSet Trait

The core abstraction is the `InstructionSet` trait, which defines everything needed to emulate an architecture:

```rust
// src/instruction_set/mod.rs

/// Minimal trait that all instruction specs must implement
/// Provides generic access to common fields
pub trait InstructionSpecTrait {
    /// Get instruction mnemonic
    fn mnemonic(&self) -> &str;

    /// Get operand pattern for parsing
    fn operands(&self) -> OperandPattern;

    /// Get description
    fn description(&self) -> &str;
}

/// Main trait defining an instruction set architecture
pub trait InstructionSet: Sized {
    /// Architecture-specific execution context
    /// This is what instruction methods receive
    type Context<'a>;

    /// Decoded operands for this architecture
    /// Different ISAs decode different operands
    type Operands;

    /// Architecture-specific instruction specification
    /// Each ISA defines its own spec type with architecture-specific encoding fields
    type Spec: InstructionSpecTrait;

    /// Architecture name for debugging
    const NAME: &'static str;

    /// Get all instruction specs (generated by proc macro)
    fn all_instructions() -> &'static [Self::Spec];

    /// Lookup instruction by mnemonic (generated by proc macro)
    fn lookup(mnemonic: &str) -> Option<&'static Self::Spec>;

    /// Lookup instruction by encoded bytes (generated by proc macro)
    fn lookup_encoding(bytes: &[u8]) -> Option<&'static Self::Spec>;

    /// Decode operands from instruction bytes
    /// Each architecture implements this based on its encoding
    fn decode_operands(bytes: &[u8], spec: &Self::Spec) -> Result<Self::Operands>;

    /// Create execution context from machine state + operands
    /// Wraps generic state in architecture-specific API
    fn create_context<'a>(
        state: &'a mut MachineState,
        spec: &Self::Spec,
        operands: Self::Operands,
    ) -> Self::Context<'a>;

    /// Execute instruction (generated by proc macro)
    /// Dispatches to appropriate method based on mnemonic
    fn execute(mnemonic: &str, ctx: &mut Self::Context<'_>) -> Result<()>;

    /// Parse assembly source code for this ISA
    /// Each ISA uses its own PEST grammar to handle ISA-specific syntax
    fn parse_assembly(source: &str) -> Result<Program>;
}
```

### Associated Types Explained

**`type Context<'a>`**: Architecture-specific execution context
- RISC-V: provides `rs1_val()`, `rs2_val()`, `set_rd()`
- 6502: provides `accumulator()`, `set_flags()`, `x_register()`
- Allows each ISA to present a natural, ergonomic API to instruction methods

**`type Operands`**: Decoded instruction operands
- RISC-V: `{ rd, rs1, rs2, imm }`
- 6502: `{ operand_byte }` (addressing mode already resolved)
- Captures what was decoded from instruction bytes

**`type Spec`**: Architecture-specific instruction specification
- RISC-V: `{ opcode, funct3, funct7, format, ... }`
- 6502: `{ opcode, addressing_mode, length, cycles, ... }`
- Each ISA defines exactly the encoding fields it needs
- Must implement `InstructionSpecTrait` for generic access to common fields

---

## Why Architecture-Specific Instruction Specs?

Different CPU architectures encode instructions in fundamentally different ways:

| Architecture | Encoding Scheme | Specific Fields Needed |
|--------------|----------------|------------------------|
| **RISC-V RV32I** | Fixed 32-bit, 6 formats | opcode (7-bit), funct3 (3-bit), funct7 (7-bit), format type |
| **6502** | Variable 1-3 bytes | opcode (8-bit), addressing mode, instruction length, cycle count |
| **ARM Thumb** | Variable 16/32-bit | opcode, condition codes, register fields, immediate encoding |
| **x86-64** | Variable 1-15 bytes | Prefixes, opcode, ModR/M, SIB, displacement, immediate |

**Key Insight:** There is no meaningful "generic" encoding representation. Trying to unify these would result in:
- ❌ Wasted fields (RISC-V doesn't have addressing modes, 6502 doesn't have funct3/funct7)
- ❌ Loss of type safety (opaque byte blobs)
- ❌ Awkward APIs (pattern matching on architecture type)

Instead, we make `Spec` an **associated type**, giving each ISA complete freedom to define its encoding structure while maintaining a minimal common interface through `InstructionSpecTrait`.

```rust
impl RV32Context<'_> {
    /// Get value of rs1 register
    pub fn rs1_val(&self) -> u32 {
        self.state.get_reg(self.rs1 as usize)
    }

    /// Get value of rs2 register
    pub fn rs2_val(&self) -> u32 {
        self.state.get_reg(self.rs2 as usize)

        self.imm

        self.state.pc += bytes;

    pub fn write_memory(&mut self, addr: u32, value: u32, width: usize) -> Result<()> {
```

### Manual Trait Implementation

```rust
impl InstructionSet for RV32I {
    type Context<'a> = RV32Context<'a>;
    type Operands = RV32Operands;
    type Spec = RV32ISpec;  // RISC-V specific instruction spec

    const NAME: &'static str = "RISC-V RV32I";

    // These methods are GENERATED by proc macro:
    // - all_instructions()
    // - lookup()
    // - lookup_encoding()
    // - execute()

    /// Decode operands from 32-bit RISC-V instruction
    fn decode_operands(bytes: &[u8], spec: &Self::Spec) -> Result<Self::Operands> {
        if bytes.len() < 4 {
            bail!("insufficient bytes for RISC-V instruction");
        }

        let word = u32::from_le_bytes([bytes[0], bytes[1], bytes[2], bytes[3]]);

        Ok(match spec.format {
            Format::R => RV32Operands {
                rd: Reg::from((word >> 7) & 0x1f),
                rs1: Reg::from((word >> 15) & 0x1f),
                rs2: Reg::from((word >> 20) & 0x1f),
                imm: 0,
            },
            Format::I => RV32Operands {
                rd: Reg::from((word >> 7) & 0x1f),
                rs1: Reg::from((word >> 15) & 0x1f),
                rs2: Reg::X0,
                imm: (word as i32) >> 20, // Sign-extend from bit 31
            },
            Format::S => RV32Operands {
                rd: Reg::X0,
                rs1: Reg::from((word >> 15) & 0x1f),
                rs2: Reg::from((word >> 20) & 0x1f),
                imm: (((word >> 25) << 5) | ((word >> 7) & 0x1f)) as i32,
            },
            Format::B => {
                let imm = ((word >> 31) << 12)
                    | (((word >> 7) & 1) << 11)
                    | (((word >> 25) & 0x3f) << 5)
                    | (((word >> 8) & 0xf) << 1);
                RV32Operands {
                    rd: Reg::X0,
                    rs1: Reg::from((word >> 15) & 0x1f),
                    rs2: Reg::from((word >> 20) & 0x1f),
                    imm: ((imm as i32) << 19) >> 19, // Sign-extend
                }
            },
            Format::U => RV32Operands {
                rd: Reg::from((word >> 7) & 0x1f),
                rs1: Reg::X0,
                rs2: Reg::X0,
                imm: (word & 0xfffff000) as i32,
            },
            Format::J => {
                let imm = ((word >> 31) << 20)
                    | (((word >> 12) & 0xff) << 12)
                    | (((word >> 20) & 1) << 11)
                    | (((word >> 21) & 0x3ff) << 1);
                RV32Operands {
                    rd: Reg::from((word >> 7) & 0x1f),
                    rs1: Reg::X0,
                    rs2: Reg::X0,
                    imm: ((imm as i32) << 11) >> 11, // Sign-extend
                }
            },
        })
    }

    /// Create execution context for RISC-V
    fn create_context<'a>(
        state: &'a mut MachineState,
        _spec: &Self::Spec,
        operands: Self::Operands,
    ) -> Self::Context<'a> {
        RV32Context {
            state,
            rd: operands.rd,
            rs1: operands.rs1,
            rs2: operands.rs2,
            imm: operands.imm,
        }
    }
}
```

### Instruction Behavior Methods

This is where the magic happens - each instruction is just a simple method:

```rust
impl RV32I {
    /// ADD: rd = rs1 + rs2
    pub fn add(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd(ctx.rs1_val().wrapping_add(ctx.rs2_val()));
        ctx.advance_pc(4);
        Ok(())
    }

    /// SUB: rd = rs1 - rs2
    pub fn sub(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd(ctx.rs1_val().wrapping_sub(ctx.rs2_val()));
        ctx.advance_pc(4);
        Ok(())
    }

    /// ADDI: rd = rs1 + imm
    pub fn addi(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd(ctx.rs1_val().wrapping_add(ctx.imm() as u32));
        ctx.advance_pc(4);
        Ok(())
    }

    /// BEQ: if rs1 == rs2 then pc += imm
    pub fn beq(ctx: &mut RV32Context) -> Result<()> {
        if ctx.rs1_val() == ctx.rs2_val() {
            ctx.branch_to(ctx.imm());
        } else {
            ctx.advance_pc(4);
        }
        Ok(())
    }

    /// LW: rd = mem[rs1 + imm]
    pub fn lw(ctx: &mut RV32Context) -> Result<()> {
        let addr = ctx.rs1_val().wrapping_add(ctx.imm() as u32);
        let value = ctx.read_memory(addr, 4)?;
        ctx.set_rd(value);
        ctx.advance_pc(4);
        Ok(())
    }

    /// SW: mem[rs1 + imm] = rs2
    pub fn sw(ctx: &mut RV32Context) -> Result<()> {
        let addr = ctx.rs1_val().wrapping_add(ctx.imm() as u32);
        ctx.write_memory(addr, ctx.rs2_val(), 4)?;
        ctx.advance_pc(4);
        Ok(())
    }

    /// JAL: rd = pc + 4; pc += imm
    pub fn jal(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd((ctx.state.pc + 4) as u32);
        ctx.branch_to(ctx.imm());
        Ok(())
    }

    /// LUI: rd = imm << 12
    pub fn lui(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd(ctx.imm() as u32);
        ctx.advance_pc(4);
        Ok(())
    }

    /// AUIPC: rd = pc + (imm << 12)
    pub fn auipc(ctx: &mut RV32Context) -> Result<()> {
        ctx.set_rd((ctx.state.pc as i64 + ctx.imm() as i64) as u32);
        ctx.advance_pc(4);
        Ok(())
    }

    // ... all other RV32I instructions
}
```

### What the Proc Macro Generates

The `#[derive(InstructionSet)]` macro reads the TOML file and generates:

```rust
// Generated constants with RISC-V specific spec type
const RV32I_INSTRUCTIONS: &[RV32ISpec] = &[
    RV32ISpec {
        mnemonic: "add",
        opcode: 0b0110011,
        funct3: Some(0b000),
        funct7: Some(0b0000000),
        format: Format::R,
        operands: OperandPattern::RdRs1Rs2,
        description: "Addition: rd = rs1 + rs2",
        category: Category::Arithmetic,
    },
    RV32ISpec {
        mnemonic: "sub",
        opcode: 0b0110011,
        funct3: Some(0b000),
        funct7: Some(0b0100000),
        format: Format::R,
        operands: OperandPattern::RdRs1Rs2,
        description: "Subtraction: rd = rs1 - rs2",
        category: Category::Arithmetic,
    },
    // ... all instructions from TOML
];

// Generated lookup methods
impl InstructionSet for RV32I {
    fn all_instructions() -> &'static [Self::Spec] {
        &RV32I_INSTRUCTIONS
    }

    fn lookup(mnemonic: &str) -> Option<&'static Self::Spec> {
        RV32I_INSTRUCTIONS.iter().find(|s| s.mnemonic == mnemonic)
    }

    fn lookup_encoding(bytes: &[u8]) -> Option<&'static Self::Spec> {
        if bytes.len() < 4 { return None; }
        let word = u32::from_le_bytes([bytes[0], bytes[1], bytes[2], bytes[3]]);
        let opcode = (word & 0x7f) as u8;
        let funct3 = ((word >> 12) & 0x7) as u8;
        let funct7 = ((word >> 25) & 0x7f) as u8;

        RV32I_INSTRUCTIONS.iter().find(|spec| {
            spec.opcode == opcode &&
            spec.funct3.map_or(true, |f3| f3 == funct3) &&
            spec.funct7.map_or(true, |f7| f7 == funct7)
        })
    }

    // Generated execute dispatcher
    fn execute(mnemonic: &str, ctx: &mut Self::Context<'_>) -> Result<()> {
        match mnemonic {
            "add" => Self::add(ctx),
            "sub" => Self::sub(ctx),
            "addi" => Self::addi(ctx),
            "beq" => Self::beq(ctx),
            "lw" => Self::lw(ctx),
            "sw" => Self::sw(ctx),
            "jal" => Self::jal(ctx),
            "lui" => Self::lui(ctx),
            "auipc" => Self::auipc(ctx),
            // ... all instructions from TOML
            _ => bail!("unknown instruction: {}", mnemonic),
        }
    }
}
```

**Compile-Time Validation:** The proc macro verifies that every instruction in the TOML has a corresponding method in the impl block. Missing method = compile error with helpful message.

### Instruction Behavior Methods

```rust
impl MOS6502 {
    /// LDA: Load accumulator
    pub fn lda(ctx: &mut MOS6502Context) -> Result<()> {
        let value = ctx.operand();
        ctx.set_accumulator(value);
        ctx.set_zero(value == 0);
        ctx.set_negative((value & 0x80) != 0);
        ctx.advance_pc(2);  // Varies by addressing mode
        Ok(())
    }

    /// ADC: Add with carry
    pub fn adc(ctx: &mut MOS6502Context) -> Result<()> {
        let a = ctx.accumulator();
        let operand = ctx.operand();
        let carry = if ctx.carry_flag() { 1 } else { 0 };

        let sum = a as u16 + operand as u16 + carry;
        let result = (sum & 0xFF) as u8;

        ctx.set_accumulator(result);
        ctx.set_carry(sum > 0xFF);
        ctx.set_zero(result == 0);
        ctx.set_negative((result & 0x80) != 0);

        // Overflow: sign(A) == sign(operand) && sign(A) != sign(result)
        let overflow = ((a ^ operand) & 0x80) == 0 && ((a ^ result) & 0x80) != 0;
        ctx.state.set_flag("V", overflow);

        ctx.advance_pc(2);
        Ok(())
    }

    /// INX: Increment X register
    pub fn inx(ctx: &mut MOS6502Context) -> Result<()> {
        let result = ctx.x_register().wrapping_add(1);
        ctx.set_x_register(result);
        ctx.set_zero(result == 0);
        ctx.set_negative((result & 0x80) != 0);
        ctx.advance_pc(1);
        Ok(())
    }

    // ... all other 6502 instructions
}
```

### Manual Trait Implementation for 6502

```rust
impl InstructionSet for MOS6502 {
    type Context<'a> = MOS6502Context<'a>;
    type Operands = MOS6502Operands;
    type Spec = MOS6502Spec;  // 6502-specific instruction spec

    const NAME: &'static str = "MOS 6502";

    // These methods are GENERATED by proc macro:
    // - all_instructions()
    // - lookup()
    // - lookup_encoding()
    // - execute()

    /// Decode operands from 6502 instruction
    /// 6502 has variable-length instructions (1-3 bytes)
    fn decode_operands(bytes: &[u8], spec: &Self::Spec) -> Result<Self::Operands> {
        if bytes.is_empty() {
            bail!("insufficient bytes for 6502 instruction");
        }

        let operand = match spec.addressing_mode {
            AddressingMode::Implied | AddressingMode::Accumulator => 0,
            AddressingMode::Immediate => {
                if bytes.len() < 2 { bail!("insufficient bytes"); }
                bytes[1]
            }
            AddressingMode::ZeroPage | AddressingMode::ZeroPageX | AddressingMode::ZeroPageY => {
                if bytes.len() < 2 { bail!("insufficient bytes"); }
                bytes[1]
            }
            AddressingMode::Absolute | AddressingMode::AbsoluteX | AddressingMode::AbsoluteY => {
                if bytes.len() < 3 { bail!("insufficient bytes"); }
                bytes[1]  // Address would need to be resolved from bytes[1] and bytes[2]
            }
            // ... other addressing modes
            _ => 0,
        };

        Ok(MOS6502Operands { operand })
    }

    /// Create execution context for 6502
    fn create_context<'a>(
        state: &'a mut MachineState,
        _spec: &Self::Spec,
        operands: Self::Operands,
    ) -> Self::Context<'a> {
        MOS6502Context {
            state,
            operand: operands.operand,
        }
    }
}
```

## The Generic Machine

The heart of the system - one machine implementation that works for any ISA:

```rust
// src/machine.rs
pub struct GenericMachine<I: InstructionSet> {
    state: MachineState,
    _phantom: PhantomData<I>,
}

/// Generic machine state that works for any architecture
pub struct MachineState {
    /// General-purpose registers (count determined by architecture)
    regs: Vec<u64>,

    /// Program counter
    pub pc: u64,

    /// Memory (byte-addressable)
    memory: Vec<u8>,

    /// Architecture-specific special registers (A, X, Y, etc.)
    special_regs: HashMap<String, u64>,

    /// Status flags (if architecture has them)
    flags: Option<u64>,
}

impl MachineState {
    pub fn new(mem_size: usize, num_regs: usize) -> Self {
        Self {
            regs: vec![0; num_regs],
            pc: 0,
            memory: vec![0; mem_size],
            special_regs: HashMap::new(),
            flags: Some(0),
        }
    }

    pub fn get_reg(&self, index: usize) -> u64 {
        if index == 0 { return 0; }  // x0 hardwired to zero
        self.regs.get(index).copied().unwrap_or(0)
    }

    pub fn set_reg(&mut self, index: usize, value: u64) {
        if index == 0 { return; }  // x0 is read-only
        if let Some(reg) = self.regs.get_mut(index) {
            *reg = value;
        }
    }

    pub fn get_special_reg(&self, name: &str) -> u64 {
        self.special_regs.get(name).copied().unwrap_or(0)
    }

    pub fn set_special_reg(&mut self, name: &str, value: u64) {
        self.special_regs.insert(name.to_string(), value);
    }

    pub fn get_flag(&self, name: &str) -> bool {
        // Implementation depends on flag definitions
        // For now, simplified
        false
    }

    pub fn set_flag(&mut self, name: &str, value: bool) {
        // Implementation depends on flag definitions
    }

    pub fn read_memory(&self, addr: u64, width: usize) -> Result<u64> {
        let addr = addr as usize;
        if addr + width > self.memory.len() {
            bail!("memory access out of bounds: {:#x}", addr);
        }

        let mut value = 0u64;
        for i in 0..width {
            value |= (self.memory[addr + i] as u64) << (i * 8);
        }
        Ok(value)
    }

    pub fn write_memory(&mut self, addr: u64, value: u64, width: usize) -> Result<()> {
        let addr = addr as usize;
        if addr + width > self.memory.len() {
            bail!("memory write out of bounds: {:#x}", addr);
        }

        for i in 0..width {
            self.memory[addr + i] = ((value >> (i * 8)) & 0xFF) as u8;
        }
        Ok(())
    }
}

impl<I: InstructionSet> GenericMachine<I> {
    pub fn new(mem_size: usize, num_regs: usize) -> Self {
        Self {
            state: MachineState::new(mem_size, num_regs),
            _phantom: PhantomData,
        }
    }

    /// Execute one instruction - works for ANY ISA!
    ///
    /// This method is completely generic - it never needs to know about:
    /// - RISC-V's opcode/funct3/funct7 fields
    /// - 6502's addressing modes or cycle counts
    /// - ARM's condition codes
    ///
    /// All ISA-specific encoding details are handled by the ISA's trait implementation.
    /// GenericMachine only uses the InstructionSpecTrait methods (mnemonic, operands, description).
    pub fn step(&mut self) -> Result<StepResult> {
        // 1. Fetch
        let pc = self.state.pc as usize;
        let bytes = &self.state.memory[pc..];

        // 2. Decode
        let spec = I::lookup_encoding(bytes)
            .ok_or_else(|| anyhow!("illegal instruction at pc={:#x}", pc))?;

        let operands = I::decode_operands(bytes, spec)?;

        // 3. Execute
        let mut ctx = I::create_context(&mut self.state, spec, operands);
        I::execute(spec.mnemonic(), &mut ctx)?;  // Use trait method

        Ok(StepResult::Continue)
    }

    pub fn run(&mut self, max_steps: usize) -> Result<()> {
        for _ in 0..max_steps {
            match self.step()? {
                StepResult::Continue => {}
                StepResult::Halt => break,
            }
        }
        Ok(())
    }

    pub fn load_program(&mut self, bytes: &[u8], addr: u64) -> Result<()> {
        let addr = addr as usize;
        if addr + bytes.len() > self.state.memory.len() {
            bail!("program too large for memory");
        }
        self.state.memory[addr..addr + bytes.len()].copy_from_slice(bytes);
        Ok(())
    }

    // Introspection methods
    pub fn get_pc(&self) -> u64 {
        self.state.pc
    }

    pub fn get_reg(&self, index: usize) -> u64 {
        self.state.get_reg(index)
    }

    pub fn dump_regs(&self) {
        for (i, &value) in self.state.regs.iter().enumerate() {
            println!("x{}: {:#010x}", i, value);
        }
    }
}

pub enum StepResult {
    Continue,
    Halt,
}

pub type MOS6502Machine = GenericMachine<MOS6502>;
```

## Assembly Syntax: The ISA-Specific Challenge

Before diving into parsing, we must recognize a fundamental truth: **different ISAs have radically different assembly syntax**.

### Syntax Differences Across ISAs

| Feature | RISC-V | 6502 | x86 (Intel) | x86 (AT&T) | ARM |
|---------|--------|------|-------------|------------|-----|
| **Comment** | `#` | `;` | `;` | `#` | `@` or `;` |
| **Register prefix** | None | None | None | `%` | None |
| **Immediate prefix** | None | `#` | None | `$` | `#` |
| **Hex notation** | `0x` | `$` | `0x` or `h` | `0x` | `0x` or `&` |
| **Memory addressing** | `()` | `()` | `[]` | `()` | `[]` |

### Example: Same Operation, Different Syntax

**RISC-V:**
```asm
add a0, a1, a2          # Add registers, comment with #
lw t0, 8(sp)            # Load with offset in parentheses
li a0, 0x42             # Immediate with 0x prefix
```

**6502:**
```asm
LDA #$42                ; Load immediate, $ for hex, ; for comment
STA $2000,X             ; Store absolute indexed
JMP ($FFFC)             ; Jump indirect
```

**x86 (AT&T syntax):**
```asm
movl 8(%ebp), %eax      # % prefix for registers, # for comment
addl $0x10, %eax        # $ prefix for immediates
```

**ARM:**
```asm
LDR r0, [r1, #4]        @ Comment with @
ADD r0, r1, r2, LSL #2  ; Barrel shifter syntax
MOV r0, #0xFF           ; # prefix for immediates
```

### Why This Matters

You **cannot** write a single generic lexer/parser for all ISAs because:

1. **Different comment syntax**: `#` vs `;` vs `@`
2. **Different prefixes**: Some ISAs require `#`, `$`, `%` for different token types
3. **Different delimiters**: `()` vs `[]` for memory addressing
4. **Different case conventions**: RISC-V lowercase, 6502 uppercase
5. **Different hex notation**: `0x` vs `$` vs `&` vs `h` suffix

**Attempting a "universal" syntax would:**
- ❌ Force unnatural syntax on ISAs (e.g., making 6502 use `#` comments)
- ❌ Lose idiomatic assembly style
- ❌ Confuse users familiar with standard ISA syntax
- ❌ Make the assembler unusable for real-world code

### The Solution: PEST with Per-ISA Grammars

Instead of fighting syntax diversity, we **embrace it**:

- Each ISA defines its own `.pest` grammar file
- PEST handles lexing and syntactic parsing
- Rust handles semantic validation using `InstructionSet` trait
- Natural, idiomatic syntax for each ISA

**Architecture:**
```
RV32I: grammars/rv32i.pest + instructions/rv32i.toml + src/isa/rv32i.rs
6502:  grammars/mos6502.pest + instructions/mos6502.toml + src/isa/mos6502.rs
```

This is truly **multi-ISA** - each architecture gets its natural syntax!

## Parser Integration

The parser transforms assembly source code into an Abstract Syntax Tree (AST). Since each ISA has different syntax, we use **PEST** - a PEG parser generator - to handle ISA-specific lexing and parsing declaratively.

### PEST: Parsing Expression Grammars

[PEST](https://pest.rs/) lets us define grammars in `.pest` files using a clean, declarative syntax. Each ISA gets its own grammar file that defines its unique assembly syntax.

### Current Problem

The existing hand-written lexer and parser are hardcoded for RISC-V syntax:

```rust

```

**Problems:**
- Lexer: 351 lines hardcoded for RISC-V (assumes `#` comments, no register prefixes, etc.)
- Parser: 353 lines with manual instruction matching
- **Cannot parse 6502, x86, ARM** - different syntax entirely
- **Duplicated across ISAs** - would need 700 lines per ISA!

### Solution: PEST Grammar Per ISA

Each ISA defines a `.pest` grammar file that describes its unique syntax.

#### Example: RISC-V Grammar (`grammars/rv32i.pest`)

```pest
// RISC-V RV32I Assembly Grammar

program = { SOI ~ line* ~ EOI }

line = _{
    (label ~ instruction?) |
    instruction |
    directive |
    NEWLINE
}

label = { identifier ~ ":" }

directive = {
    "." ~ "global" ~ identifier |
    "." ~ "section" ~ "." ~ identifier |
    "." ~ "ascii" ~ string
}

instruction = { mnemonic ~ operands? ~ comment? }

operands = { operand ~ ("," ~ operand)* }

operand = _{
    offset_address |
    register |
    immediate |
    symbol
}

offset_address = { immediate ~ "(" ~ register ~ ")" }
register = @{ (ASCII_ALPHA | "_") ~ (ASCII_ALPHANUMERIC | "_")* }
immediate = { "-"? ~ (hex_number | dec_number) }
symbol = @{ (ASCII_ALPHA | "_") ~ (ASCII_ALPHANUMERIC | "_")* }

mnemonic = @{ ASCII_ALPHA+ }
identifier = @{ (ASCII_ALPHA | "_") ~ (ASCII_ALPHANUMERIC | "_")* }

hex_number = @{ "0x" ~ ASCII_HEX_DIGIT+ }
dec_number = @{ ASCII_DIGIT+ }

string = @{ "\"" ~ ( "\\\"" | (!("\"") ~ ANY) )* ~ "\"" }
comment = @{ "#" ~ (!NEWLINE ~ ANY)* }

WHITESPACE = _{ " " | "\t" }
```

**Features:**
- `#` for comments (RISC-V standard)
- `offset(register)` syntax for memory addressing
- `0x` prefix for hex numbers
- Lowercase identifiers
- Directives start with `.`

#### Example: 6502 Grammar (`grammars/mos6502.pest`)

```pest
// MOS 6502 Assembly Grammar

program = { SOI ~ line* ~ EOI }

line = _{
    (label ~ instruction?) |
    instruction |
    NEWLINE
}

label = { identifier ~ ":" }

instruction = { mnemonic ~ operands? ~ comment? }

operands = { operand ~ ("," ~ register_index)? }

operand = _{
    immediate_hex |      // #$42
    immediate_dec |      // #42
    absolute_indexed_x | // $2000,X
    absolute_indexed_y | // $2000,Y
    indirect |           // ($FFFC)
    indirect_x |         // ($20,X)
    indirect_y |         // ($20),Y
    absolute |           // $2000
    zeropage |           // $20
    register             // A, X, Y
}

immediate_hex = { "#" ~ "$" ~ hex_digit+ }
immediate_dec = { "#" ~ ASCII_DIGIT+ }
absolute_indexed_x = { "$" ~ hex_digit+ ~ "," ~ "X" }
absolute_indexed_y = { "$" ~ hex_digit+ ~ "," ~ "Y" }
indirect = { "(" ~ "$" ~ hex_digit+ ~ ")" }
indirect_x = { "(" ~ "$" ~ hex_digit+ ~ "," ~ "X" ~ ")" }
indirect_y = { "(" ~ "$" ~ hex_digit+ ~ ")" ~ "," ~ "Y" }
absolute = { "$" ~ hex_digit+ }
zeropage = { "$" ~ hex_digit{2} }

register_index = { "X" | "Y" }
register = { "A" | "X" | "Y" }

mnemonic = @{ ASCII_ALPHA{3} }  // 6502 mnemonics are exactly 3 letters
identifier = @{ (ASCII_ALPHA | "_") ~ (ASCII_ALPHANUMERIC | "_")* }

hex_digit = _{ ASCII_HEX_DIGIT }
comment = @{ ";" ~ (!NEWLINE ~ ANY)* }

WHITESPACE = _{ " " | "\t" }
```

**Features:**
- `;` for comments (6502 standard)
- `#` prefix for immediates
- `$` prefix for hex addresses
- Complex addressing modes (indirect indexed, etc.)
- Uppercase mnemonics
- Exactly 3-letter mnemonics

### How PEST Works

1. **Define grammar** in `.pest` file
2. **Derive parser** using `#[derive(Parser)]`
3. **Parse source** to get `Pairs` (parse tree)
4. **Convert to AST** using semantic validation

### Semantic Parsing with InstructionSet Trait

PEST handles **syntax** ("does this look like valid assembly?"), but we still need **semantic validation** ("is this a valid instruction with correct operands?").

Each ISA implements `parse_assembly()` to convert PEST parse tree to validated AST:

```rust
use pest::Parser;
use pest_derive::Parser;

// Define PEST parser for RISC-V
#[derive(Parser)]
#[grammar = "grammars/rv32i.pest"]
pub struct RV32IParser;

impl InstructionSet for RV32I {
    // ... other trait methods ...

    fn parse_assembly(source: &str) -> Result<Program> {
        // 1. Parse syntax with PEST
        let pairs = RV32IParser::parse(Rule::program, source)
            .map_err(|e| anyhow!("Parse error: {}", e))?;

        // 2. Convert to AST with semantic validation
        let mut program = Program { lines: vec![] };

        for pair in pairs {
            for line_pair in pair.into_inner() {
                match line_pair.as_rule() {
                    Rule::label => {
                        let name = line_pair.into_inner().next().unwrap().as_str();
                        program.lines.push(Line::Label(name.to_string()));
                    }

                    Rule::directive => {
                        let directive = Self::parse_directive(line_pair)?;
                        program.lines.push(Line::Directive(directive));
                    }

                    Rule::instruction => {
                        let instruction = Self::parse_instruction(line_pair)?;
                        program.lines.push(Line::Instruction(instruction));
                    }

                    Rule::EOI => break,
                    _ => {}
                }
            }
        }

        Ok(program)
    }

    fn parse_instruction(pair: Pair<Rule>) -> Result<Instruction> {
        let mut inner = pair.into_inner();

        // Get mnemonic
        let mnemonic = inner.next().unwrap().as_str().to_string();

        // SEMANTIC VALIDATION: Lookup instruction spec
        let spec = Self::lookup(&mnemonic)
            .ok_or_else(|| anyhow!("unknown instruction: {}", mnemonic))?;

        // Parse operands from PEST pairs
        let operands = if let Some(operands_pair) = inner.next() {
            Self::parse_operands(operands_pair)?
        } else {
            vec![]
        };

        Ok(Instruction {
            name: mnemonic,
            operands,
        })
    }

    fn parse_operands(pair: Pair<Rule>) -> Result<Vec<Operand>> {
        let mut operands = vec![];

        for operand_pair in pair.into_inner() {
            let operand = match operand_pair.as_rule() {
                Rule::register => {
                    let name = operand_pair.as_str().to_string();
                    Operand::Register(name)
                }

                Rule::immediate => {
                    let value_str = operand_pair.as_str();
                    let value = if value_str.starts_with("0x") {
                        i32::from_str_radix(&value_str[2..], 16)?
                    } else {
                        value_str.parse::<i32>()?
                    };
                    Operand::ImmI32(value)
                }

                Rule::offset_address => {
                    let mut inner = operand_pair.into_inner();
                    let imm_str = inner.next().unwrap().as_str();
                    let imm = if imm_str.starts_with("0x") {
                        i32::from_str_radix(&imm_str[2..], 16)?
                    } else {
                        imm_str.parse::<i32>()?
                    };
                    let register = inner.next().unwrap().as_str().to_string();

                    Operand::OffsetAddress { imm, register }
                }

                Rule::symbol => {
                    let name = operand_pair.as_str().to_string();
                    Operand::Symbol(name)
                }

                _ => bail!("unexpected operand type: {:?}", operand_pair.as_rule()),
            };

            operands.push(operand);
        }

        Ok(operands)
    }
}
```

**Key points:**
- PEST parses syntax → we get structured `Pairs`
- `lookup()` validates instruction exists
- Convert PEST rules to AST `Operand` enum
- Can add additional semantic validation here

### Syntax vs Semantics Separation

This is the beauty of the PEST approach:

| Layer | Responsibility | Example Question |
|-------|---------------|------------------|
| **PEST Grammar** | Syntax | "Does `add a0, a1, a2` match instruction grammar?" |
| **InstructionSet::lookup()** | Instruction validation | "Does RV32I have an `add` instruction?" |
| **OperandPattern** (optional) | Operand validation | "Does `add` expect 3 registers?" |

The grammar says "this looks like an instruction with 3 comma-separated operands", and the trait validates "RV32I has `add` and it needs 3 register operands".

- Simpler architecture overall

### What the Macro Does

1. **Parse attribute**: Extract TOML path from `#[instruction_set(path = "...")]`
2. **Read TOML**: Load and parse instruction definitions at compile time
3. **Validate TOML**: Check that all fields are valid, opcodes are in range, etc.
4. **Generate ISA-specific spec constants**: Create array of `RV32ISpec` or `MOS6502Spec` (not generic!)
5. **Generate lookup functions**: Create `lookup()` and `lookup_encoding()` returning `&'static Self::Spec`
6. **Generate execute dispatcher**: Create match statement calling methods
7. **Validate methods exist**: Use syn to check that impl block has all required methods

**Key Point**: The proc macro generates **ISA-specific code**. For RISC-V, it generates an array of `RV32ISpec` structs with `opcode`, `funct3`, `funct7` fields. For 6502, it generates an array of `MOS6502Spec` structs with `opcode`, `addressing_mode`, `length`, `cycles` fields. The macro reads the TOML and maps fields to the appropriate Spec struct based on what that ISA needs.

### Compile-Time Validation

The macro performs extensive validation:

```rust
// Pseudo-code for validation
for instruction in toml.instructions {
    // Validate encoding fields
    assert!(instruction.opcode <= 0x7f, "opcode must be 7 bits");
    assert!(instruction.funct3.map_or(true, |f| f <= 0x7), "funct3 must be 3 bits");

    // Validate mnemonic matches method name
    let method_name = format_ident!("{}", instruction.mnemonic);
    assert!(
        impl_block_has_method(method_name),
        "Missing method for instruction '{}'",
        instruction.mnemonic
    );
}
```

**If validation fails:** Compile error with helpful message pointing to the problem.

## Advantages of This Design

### ✅ Architecture-Specific Specs with Type Safety

The `type Spec: InstructionSpecTrait` associated type is a key design decision that provides:

**Flexibility:**
- RISC-V defines `RV32ISpec` with `opcode`, `funct3`, `funct7`, `format`
- 6502 defines `MOS6502Spec` with `opcode`, `addressing_mode`, `length`, `cycles`
- Each ISA includes exactly the encoding fields it needs, nothing more

**Type Safety:**
- Can't accidentally pass `RV32ISpec` to 6502 code - compile error
- Can't mix instruction specs between ISAs
- Compiler verifies all spec usages are correct

**Zero Waste:**
- No generic "one size fits all" struct with optional fields
- No opaque byte blobs losing type information
- Each ISA's spec is optimally sized and typed

**Generic Code Still Works:**
- GenericMachine uses `I::Spec` but only accesses `InstructionSpecTrait` methods
- Generic code calls `spec.mnemonic()`, `spec.operands()`, `spec.description()`
- ISA-specific code accesses encoding fields directly (e.g., `spec.opcode`, `spec.funct3`)

### ✅ Zero Runtime Overhead

- Generic `GenericMachine<I>` is monomorphized at compile time
- Each `RV32IMachine` gets its own optimized `step()` function
- No trait object dispatch (no `dyn InstructionSet`)
- Context methods can be inlined
- Compiler can optimize across the entire execution path

### ✅ Zero Code Duplication

- **ONE** `GenericMachine::step()` implementation
- Works for RISC-V, 6502, ARM, x86, custom ISAs
- No per-ISA fetch-decode-execute loops
- No enum matching on ISA types

### ✅ Type Safety

- Can't accidentally use RISC-V context in 6502 code
- Compile-time verification that TOML ↔ methods match
- Wrong operand types = compile error
- Missing instruction method = compile error

### ✅ Natural, Ergonomic APIs

- RISC-V gets `rs1_val()`, `set_rd()`, `branch_to()`
- 6502 gets `accumulator()`, `set_flags()`, `x_register()`
- Each architecture presents the API that makes sense for it
- No awkward generic abstractions

### ✅ Easy to Extend

**Adding an instruction:**
1. Add one entry to TOML (encoding metadata)
2. Add one method to impl block (behavior)
3. Done!

**Adding an ISA:**
1. Create TOML file with instruction definitions
2. Create struct with `#[derive(InstructionSet)]`
3. Implement `decode_operands()` and `create_context()`
4. Write instruction methods
5. Done!

### ✅ Educational Value

Demonstrates modern Rust patterns:
- Associated types
- Generic programming
- Procedural macros
- Compile-time code generation
- Type-driven design

## Comparison with Alternatives

### Alternative 1: Separate Machine per ISA

```rust
pub struct RV32IMachine { /* ... */ }
pub struct MOS6502Machine { /* ... */ }
```

**Pros:** No abstraction overhead, simplest mental model
**Cons:** Duplicate fetch-decode-execute logic, can't write ISA-agnostic tools

### Alternative 2: Enum Dispatch

```rust
pub enum ISA { RV32I, MOS6502 }
pub struct GenericMachine {
    isa: ISA,
    // ...
}
```

**Pros:** Runtime ISA switching
**Cons:** Match on every operation, can't use type system, runtime overhead

### Alternative 3: Behavior in TOML

```toml
[instruction]
mnemonic = "add"
behavior = "AluReg"
alu_op = "add"
```

**Pros:** Declarative
**Cons:** Limited expressiveness, string references, harder debugging

### Our Choice: Trait-Based with Method Behaviors

Combines the best of all approaches:
- Generic like Alternative 1, but with shared logic
- Type-safe unlike Alternative 2
- Flexible unlike Alternative 3
- Co-located: encoding (TOML) + behavior (methods) in same module

## Usage Examples

### Creating and Running a Machine

```rust
use rmachine_core::machine::GenericMachine;
use rmachine_rv32i::RV32I;

// Type alias for convenience
type RV32IMachine = GenericMachine<RV32I>;

fn main() -> Result<()> {
    // Create RISC-V machine: 64KB memory, 32 registers
    let mut machine = RV32IMachine::new(64 * 1024, 32);

    // Load program binary
    let program = std::fs::read("program.bin")?;
    machine.load_program(&program, 0x0000)?;

    // Run program
    machine.run(10000)?;

    // Inspect results
    println!("PC: {:#x}", machine.get_pc());
    println!("a0 (x10): {:#x}", machine.get_reg(10));

    Ok(())
}
```

### Debugging Individual Instructions

```rust
#[test]
fn test_add_instruction() {
    let mut machine = RV32IMachine::new(1024, 32);

    // Set up registers
    machine.state.set_reg(1, 10);  // x1 = 10
    machine.state.set_reg(2, 20);  // x2 = 20

    // Load instruction: add x3, x1, x2
    let instruction = encode_r_type(0b0110011, 3, 0b000, 1, 2, 0b0000000);
    machine.state.memory[0..4].copy_from_slice(&instruction);

    // Execute
    machine.step().unwrap();

    // Verify
    assert_eq!(machine.get_reg(3), 30);  // x3 = 10 + 20
    assert_eq!(machine.get_pc(), 4);     // PC advanced
}
```

### ISA-Agnostic Tools

```rust
use rmachine_core::instruction_set::InstructionSet;
use rmachine_rv32i::RV32I;
use rmachine_mos6502::MOS6502;

fn disassemble<I: InstructionSet>(bytes: &[u8]) -> String {
    if let Some(spec) = I::lookup_encoding(bytes) {
        format!("{} ({})", spec.mnemonic(), I::NAME)
    } else {
        format!(".byte {:02x?}", bytes)
    }
}

// Works for any ISA!
println!("{}", disassemble::<RV32I>(&[0x33, 0x05, 0xB5, 0x00]));
println!("{}", disassemble::<MOS6502>(&[0xA9, 0x42]));
```

## Conclusion

This trait-based architecture with workspace structure provides:

1. **Generic emulation framework** - write instruction set once, get full emulator
2. **Zero overhead abstraction** - compile-time generics, no runtime cost
3. **Type safety** - can't mix architectures, compile-time validation
4. **Natural APIs** - each ISA gets ergonomic, architecture-specific context
5. **Easy extension** - add instructions with one TOML entry + one method
6. **Modular crate structure** - clean separation, parallel compilation, independent ISA development
7. **Educational value** - demonstrates advanced Rust patterns

The design transforms rmachine from a RISC-V emulator into a universal emulation platform, while maintaining the simplicity and performance of hand-written code. The workspace structure ensures each ISA is self-contained and can be developed, tested, and published independently.

**Key insights:**
1. **The pattern of emulation is generic** (fetch-decode-execute), but architectural details are specific
2. **Instruction encoding is inherently ISA-specific** - RISC-V opcodes have nothing to do with 6502 addressing modes
3. **Assembly syntax is inherently ISA-specific** - RISC-V uses `#` comments, 6502 uses `;`, x86 AT&T uses `%` for registers
4. **Associated types provide the perfect abstraction** - generic code uses `I::Spec` through the trait, ISA-specific code accesses concrete fields
5. **PEST handles syntax diversity** - declarative grammars let each ISA define natural syntax without code duplication
6. **Workspace structure enables modularity** - each ISA is a self-contained crate with its own grammar, specs, and implementation
7. **Four components per ISA work together**:
   - `.pest` file - Assembly syntax rules (declarative)
   - `.toml` file - Instruction encoding specs (data)
   - `.rs` file - Instruction behaviors (code)
   - `InstructionSet` trait - Semantic validation (interface)

Rust's trait system with associated types + PEST's declarative grammars + Cargo workspace modularity let us capture both the generic pattern and the specific details elegantly, with massive code reduction (85%!) and zero runtime overhead.
